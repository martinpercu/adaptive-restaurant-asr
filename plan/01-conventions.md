# 01 — Conventions (Normative)

Every rule in this document is **mandatory**. When code and this document disagree, this document wins; fix the code. When this document is silent, choose the simplest option consistent with it and record the choice in [DECISIONS.md](DECISIONS.md).

## 1. Audio format

- Canonical format everywhere: **WAV, PCM 16-bit, 16 kHz, mono**. Convert at ingest; never store anything else in datasets.
- All audio I/O through `soundfile` (read/write) and `torchaudio` (transforms). Do not add `librosa` as a core dependency.
- In-memory representation: `np.ndarray`, `dtype=float32`, range [−1.0, 1.0], shape `(samples,)`.

## 2. Languages

- Supported languages: `es` and `en`. Every dataset, eval set, lexicon, confusion rule, and metric report carries a `lang` field with exactly one of these values.
- Language detection at inference is clamped to `{es, en}`: take Whisper's detected-language probabilities and pick the higher of the two, never a third language.
- All metric gates are evaluated **per language**. A gate passes only if it passes for both `es` and `en`.

## 3. Noise taxonomy

### 3.1 Codes

`noise-<SUBTYPE>-<LEVEL>` where `SUBTYPE` is two uppercase letters (first letter = family) and `LEVEL` is a two-digit volume code.

Registry lives in `configs/noise_taxonomy.yaml` — the single source of truth. Seed content:

```yaml
families:
  A: {name: kitchen}
  B: {name: outdoor}
  C: {name: front-of-house}
  D: {name: music-media}
subtypes:
  AA: {family: A, name: dishes-cutlery,     desc: "plates, cutlery clatter, glass clinks"}
  AB: {family: A, name: fryer-extractor,    desc: "fryer sizzle, extractor hood, stationary hum"}
  AC: {family: A, name: kitchen-babble,     desc: "multiple staff voices talking in kitchen"}
  BA: {family: B, name: drive-thru-traffic, desc: "car engines, idling, street traffic at the lane"}
  BB: {family: B, name: construction,       desc: "jackhammer, drilling, hammering"}
  BC: {family: B, name: car-cabin,          desc: "voices/radio inside the customer's car (passengers, kids shouting) over an engine bed — the primary drive-thru babble source"}
  CA: {family: C, name: dining-babble,      desc: "customers talking in dining room"}
  CB: {family: C, name: music,              desc: "background music / radio"}
levels:
  "05": {snr_db: 10.0,  name: low}
  "10": {snr_db: 0.0,   name: equal}   # noise RMS == clean speech RMS
  "15": {snr_db: -5.0,  name: high}
  "20": {snr_db: -10.0, name: extreme} # optional stress level, not part of the canonical grid
```

- **Canonical grid** = all subtypes × levels {05, 10, 15}. Level 20 is opt-in for stress tests only (it causes WER ceiling effects that reduce diagnostic discrimination).
- New subtypes are appended, never renamed or reused. Adding a subtype = one YAML entry + noise assets; everything downstream discovers it from the registry.

### 3.2 SNR semantics

SNR is computed against **speech-active RMS** (RMS over VAD-active frames of the clean utterance), not whole-file RMS. Noise RMS is over the full noise segment used. Level `10` ⇔ SNR 0 dB ⇔ noise RMS equals speech-active RMS — this matches the product definition "volume 10 is identical to the clean audio volume".

## 4. Identifiers

| Entity | Pattern | Example |
|--------|---------|---------|
| Clean utterance | `cl-<lang>-<seq:05d>` | `cl-es-00042` |
| Noise clip (bank asset) | `nz-<SUBTYPE>-<seq:04d>` | `nz-AB-0007` |
| Noisy (mixed) utterance | `<clean_id>__noise-<SUBTYPE>-<LEVEL>` | `cl-es-00042__noise-AB-15` |
| Dataset | `<purpose>-<lang or 'xx'>-v<int>` | `eval-matrix-es-v1`, `train-noisy-xx-v3` |
| Model version | semver `MAJOR.MINOR.PATCH` | `1.3.0` |
| LoRA adapter | `lora-<ISO week>` | `lora-2026w29` |
| Confusion rule | `<lang>-<seq:04d>` | `es-0001` |
| Metrics run | `run-<UTC timestamp>Z-<model version>` | `run-20260717T120000Z-1.3.0` |

Mixed-utterance filenames use the ID verbatim + `.wav`. IDs are immutable; regeneration with different parameters requires a new dataset version.

## 6. Code conventions

- Python ≥ 3.11. Package manager: `uv` (fallback: `pip`). Lint/format: `ruff` (line length 100). Type hints on all public functions; `pydantic` models for every cross-module data structure.
- Every subsystem exposes a CLI: `python -m ars.<module> <command> --config configs/default.yaml`. No notebook-only logic.
- **Determinism**: any stochastic process (mixing, sampling, training data selection) takes an explicit `seed`; default seed is `1337`; the seed used is recorded in the output manifest.
- Logging: `structlog` JSON lines to stdout; per-request trace IDs. Never log raw audio content or full customer transcripts at INFO level (see privacy, phase 7).
- Config: one root `configs/default.yaml` validated by `ars.config.Settings` (pydantic-settings). Env-var overrides via `ARS_` prefix. No module reads YAML directly.

## 7. Testing conventions

Full detail in [testing/test-strategy.md](testing/test-strategy.md). Non-negotiables:

- Markers: `acceptance` (phase gates), `slow`, `gpu`, `network`. CI (CPU) runs everything unmarked plus `golden`; `acceptance` runs via `make gate PHASE=N`.
- Audio fixtures are **generated** by `tests/conftest.py` (seeded numpy: tones, shaped noise, chirps, silence) — never commit binaries > 100 KB.
- Numeric tolerances: SNR assertions ± 0.5 dB; WER comparisons on 3-decimal floats; CT2-vs-HF parity ≤ 1.0 absolute WER point.
- CI uses `whisper-tiny` to keep runtimes sane; gates that need real model sizes are `slow` and run locally/GPU.

## 8. Hard rules for the builder

1. **Never weaken a gate to pass it.** If a gate fails, fix the system or escalate in DECISIONS.md with evidence.
2. Never commit anything under `data/`, `models/` (except `models/registry.json`), or `reports/` beyond manifests/READMEs.
3. Never hand-edit generated files (`configs/mitigation_policy.yaml`, registry files, reports).
4. All timestamps UTC ISO-8601 with `Z` suffix.
5. Every new confusion rule ships with its golden positive **and** negative test in the same commit.
6. Docs in English; user-facing strings in the transcript pipeline stay in the utterance's language.
