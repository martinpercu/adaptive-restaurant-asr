# Phase 7 — Hardening, Observability & Real-Data Onboarding

**Goal:** make the system operable and ready for real restaurants: dashboards, drift alarms, per-store profiles, security/privacy, load behavior, and the protocol for replacing public/synthetic data with the real thing. No new ML — this phase is about running what exists safely.
**Depends on:** phase 6 gate. **Estimated effort:** 5–8 days, then ongoing.

## Deliverables

- `src/ars/eval/dashboard.py` — static HTML report generator (jinja2 + matplotlib; no server dependency): fleet WER proxies, NDI trends, rule fire rates, latency percentiles, per-store noise profiles.
- Drift monitors + alerting hooks.
- Security/privacy hardening (API auth, retention, log scrubbing).
- `docs/RUNBOOKS.md` (in repo root `docs/`, created this phase) — operational procedures.
- `docs/FIELD-RECORDING-PROTOCOL.md` — how to capture real restaurant audio correctly.
- Load test results + capacity notes.

## Tasks

### 7.1 Dashboard
`python -m ars.eval.dashboard --out reports/dashboard/` regenerated by the weekly cycle: model version history + gate results; WER proxy trend (judge-scored samples); confidence distribution per store; NDI evolution across sensitivity runs; keydetector: rules fired/week, top rules, false-correction incidents; latency p50/p95/p99 per stage. Single self-contained HTML per section.

### 7.2 Drift monitors
Weekly computations with alert thresholds (config): PSI of `avg_logprob` distribution vs trailing 4-week reference > 0.2 → "input drift"; noise-profile subtype share change > 2× → "noise drift" (already flagged by 6.6 — wire to alerts); rule fire rate spike > 3× weekly mean → "rule storm" (possible over-correction); judge `wrong+hallucination` share > 15% → "quality alarm". Alert = structured log + optional webhook URL (config; no vendor lock).

### 7.3 Security & privacy
- API: bearer token auth (static per-store tokens in config/env), rate limit per store, max upload duration 60 s.
- PII policy: raw audio retention 90 days then delete (scheduled task); transcripts pseudonymized in telemetry (hash store+trace ids); no payment-card or name extraction anywhere; document lawful-basis note for call recording per deployment jurisdiction (placeholder for legal review).
- Log scrubbing test: telemetry lines contain no full final transcripts at INFO (config flag for debug environments only).

### 7.4 Load & capacity
Simple load runner (`scripts/load_test.py`, asyncio): sustained 4× expected per-store request rate against the CPU container → p95 within budget, no memory growth over 30 min. Document per-container concurrency and horizontal scaling notes (stateless API; DB/registry contention analysis).

### 7.5 Field recording protocol (`docs/FIELD-RECORDING-PROTOCOL.md`)
For each store daypart (open/rush/close): 10-min **noise-only** captures at the actual mic position (drive-thru mic first — it is the primary channel — then counter mic). At outdoor mics, log weather/wind conditions per capture; once real recordings exist, register a dedicated `BD wind-weather` subtype (reserved; not in the bootstrap grid because no public proxy is faithful) → curated into the noise bank as `own-recording` clips under the correct subtype (these progressively replace public proxies — expect NDI shifts; rerun sensitivity after each batch). Plus real order audio: consent signage requirements, gain staging (peak −12 dBFS, no AGC if avoidable, note mic model + gain in sidecar meta), minimum 500 real utterances transcribed via the review queue → first **real ground-truth eval set** `eval-real-<lang>-v1`. From then on, all promotion gates run on real eval sets; synthetic sets remain as regression suites.

### 7.6 Optional enrichment
Common Voice (auth download) to widen accent coverage; extra TTS voices; level-20 stress rows in sensitivity runs. Each optional, each behind a DECISIONS.md entry.

## Acceptance tests (`tests/acceptance/test_phase7_*.py`)

1. `test_dashboard_generates` — fixture DB/reports → all HTML sections render, no missing-data crashes (empty-state handled).
2. `test_drift_monitors` — synthetic distributions triggering each alarm exactly at threshold; below-threshold silent.
3. `test_api_auth_and_limits` — no token → 401; bad token → 403; oversize audio → 413; rate limit → 429.
4. `test_retention_job` — fixture files older than retention → deleted; manifests updated; newer files untouched (dry-run mode exists and is default).
5. `test_log_scrubbing` — INFO telemetry contains no transcript text field when scrubbing on.
6. `test_load_smoke` (`slow`) — 10× concurrent 5 s requests complete within 3× single-request latency.
7. `test_runbooks_exist` — RUNBOOKS.md covers: model rollback, rule retirement, flywheel pause, judge outage, disk-full, restore-from-backup; each with exact commands (doc-lint style test: required section headers present).

## Pitfalls
- Real mics change everything: gain structure, frequency response, room acoustics. Never assume public-noise NDI rankings survive contact with real stores — that's *why* the sensitivity runner is cheap to re-run.
- Deleting raw audio on retention must not orphan DB rows — soft-delete with `audio_purged=true`, keep transcripts/metrics.
- Rate limiting per store, not global — one broken kiosk must not starve the fleet.
